# Weather converter unification & SWAT2012/SWAT+ format fixes

Date: 2026-08-31
Status: Approved for planning

## Problem

`swatprep`'s "raw vendor data → final SWAT format" weather pipeline is split
across three loosely related converter classes with duplicated,
inconsistent, and in places incorrect file-writing logic:

- `converters/swat2012.py` (`PCPConverter`, `TmpConverter`) reads raw
  per-station files (SWAT Classic style or CSV) and writes SWAT2012
  `.pcp`/`.tmp` files directly, with its own header-writing code.
- `converters/weather_plus.py` (`SWATPlusWeatherConverter`) reads *merged*
  per-station CSVs and writes SWAT+ `.pcp`/`.tmp`/`.hmd`/`.slr`/`.wnd` +
  `.cli` index files, with its own separate header-writing code.
- `cli.py::convert_swatplus` glues the two together by instantiating
  `PCPConverter`/`TmpConverter`, reaching into their **private** methods
  (`_find_raw_file`, `_is_swat_format`, `_read_swat_pcp`, `_read_swat_tmp`),
  manually merging the result into a `tempfile.mkdtemp()` directory, and
  handing that to `SWATPlusWeatherConverter`.

This produces two concrete bugs, found by comparing current output against
real reference data (see "Reference data" below):

1. **SWAT2012 header/date bug** — `writers/weather.py` (used by the main
   `build()` pipeline) writes a 4-line `title / Lati / Long / Elev` header
   before the data, and writes the **day before** the first data record as
   the start-date line. Real SWAT2012 station files have neither: no
   metadata header block, and the start-date line is the actual date of the
   first record.
2. **Missing SWAT+ linking files** — `SWATPlusWeatherConverter` /
   `SWATPlusWeatherWriter` write correctly-formatted `.pcp`/`.tmp`/... data
   files and their per-variable `.cli` index files, but never write
   `weather-sta.cli` (the station registry SWAT+ actually reads to resolve
   each station's data files) or `weather-wgn.cli` (the WGN statistics file
   in SWAT+'s real fixed format). Without these two files, swatprep's SWAT+
   output cannot be dropped into a `TxtInOut` folder as-is.

## Architecture

Core idea: converters should only be responsible for *reading* raw vendor
input into the existing `WeatherResult` type (`core/weather.py`); *writing*
stays the sole responsibility of the existing `WeatherWriter` /
`SWATPlusWeatherWriter` classes, which already back the config-driven
`build()` pipeline. This removes all duplicate/inconsistent format-writing
code and gives the whole tool one single source of truth per output format.

```
raw station files (SWAT Classic style or CSV)
         |
         v
StationWeatherConverter.convert()   <- reads pcp/tmp master + data dirs,
         |                             auto-detects SWAT Classic vs CSV
         v
   WeatherResult                    <- same type core/weather.py already
         |                             produces for the build() pipeline
         |
         +-- target="swat2012" --> WeatherWriter        (fixed format)
         +-- target="swatplus" --> SWATPlusWeatherWriter (+ new .cli files)
```

`converters/swat2012.py` and `converters/weather_plus.py` are deleted;
their raw-reading logic (SWAT Classic format detection, CSV fallback,
station/file matching) moves into the new `StationWeatherConverter`.
`converters/climate.py` (`DayFilesConverter`, Vietnamese `.day` files) and
`converters/streamflow.py` are untouched — different input shape, not part
of this problem.

### `StationWeatherConverter`

New file: `swatprep/converters/station_weather.py`.

Mirrors the shape `WeatherConfig.precip` / `WeatherConfig.temp` already use
(`config.py`), instead of inventing new parameter names:

```python
class StationWeatherConverter:
    def __init__(
        self,
        pcp_master: Path | None = None, pcp_dir: Path | None = None,
        tmp_master: Path | None = None, tmp_dir: Path | None = None,
        name_col="NAME", lat_col="LAT", lon_col="LONG", elev_col="ELEVATION",
        pcp_name_prefix="pcp_", tmp_name_prefix="tmp_",
    ) -> None: ...

    def convert(self) -> WeatherResult: ...
```

- At least one of the `pcp_*` / `tmp_*` group must be given.
- Master files use the SWAT2012 convention: uppercase columns
  `ID,NAME,LAT,LONG,ELEVATION`. Station id/lat/lon/elev map onto
  `WeatherResult.stations`'s existing (lowercase) internal representation.
- Raw per-station file reading (SWAT Classic 8-digit-date detection, CSV
  fallback, `tmin,tmax` pair parsing) reuses the logic currently private in
  `_BaseStationConverter`/`PCPConverter`/`TmpConverter`, consolidated here
  as shared internal helpers instead of duplicated across three classes.
- Missing per-station raw file, missing columns, etc. produce `QACheck`
  warnings (as today) rather than hard failures — one bad station doesn't
  block the rest.

## SWAT2012 output format fix (applies globally to `WeatherWriter`)

This fixes `writers/weather.py`, used both by `build()` and by the new
converter — one writer, one correct format, and
`docs/WEATHER_OUTPUT.md` is updated to match.

**Per-station file** (`{NAME}.txt`, e.g. `pcp_ANKHE.txt` / `tmp_ANKHE.txt`):

```
YYYYMMDD          <- date of the FIRST data record (no day-before offset)
0.0
0.3
1.5
...
```

- No `title` / `Lati` / `Long` / `Elev` header block.
- pcp: one value per line. tmp: `tmin,tmax` per line (existing order kept).
- Values written without fixed-width padding (plain, compact — matching
  reference style), not `%10.3f`.
- Missing data still written as `-99.0` (existing whole-codebase
  convention; reference data was a contiguous series so doesn't exercise
  this case, but the writer must keep handling gaps).
- File extension is `.txt`, matching the reference convention — not `.pcp`.

**Master (metadata) file** — replaces the lowercase `stations.csv` /
`precip_stations.csv` / `temp_stations.csv` that `WeatherWriter` currently
writes, when the target is SWAT2012:

- `master_pcp.txt` (if precip stations present), `master_tmp.txt` (if temp
  stations present).
- Columns uppercase: `ID,NAME,LAT,LONG,ELEVATION`.
- `NAME` = station name with the domain prefix re-applied (`pcp_`/`tmp_`),
  e.g. station `ANKHE` → `NAME=pcp_ANKHE` in `master_pcp.txt`.
- `ID` = the station's existing `id` value from `WeatherResult.stations`
  (passed through, not regenerated).

## CLI surface

Replace `convert pcp`, `convert tmp`, `convert swatplus` with one command:

```bash
swatprep convert weather \
  --pcp-master master_pcp.txt --pcp-dir ./raw_pcp \
  --tmp-master master_tmp.txt --tmp-dir ./raw_tmp \
  --target swat2012 --target swatplus \
  OUT_DIR
```

- `--pcp-*` and `--tmp-*` groups are each optional but at least one must be
  given (validated the same way `StationWeatherConverter` validates it).
- `--target` may be repeated (mirrors `project.targets` in `config.yaml`).
  When more than one target is given, each is written to its own
  subdirectory (`OUT_DIR/swat2012/`, `OUT_DIR/swatplus/`), reusing the
  `multi = len(...) > 1` convention already in `api.py`'s `build()`.
- `convert climate` and `convert streamflow` are unchanged.
- This is a breaking CLI change (`convert pcp`/`tmp`/`swatplus` removed, no
  deprecated aliases) — acceptable given the project is pre-1.0 (`0.1.0`).

## SWAT+ completeness: `weather-sta.cli` + `weather-wgn.cli`

Added to `SWATPlusWeatherWriter` (`writers/weather_plus.py`), written after
the existing per-variable data files and `.cli` index files.

**`weather-wgn.cli`** — built directly from the already-computed
`WeatherResult.wgn_stats` (`core/_wgn.py` already computes all 14 SWAT+ WGN
fields — this is a new writer, not new computation):

- One WGN group per station (group name = station name — the simplest
  mapping; avoids introducing a separate WGN grid-cell system).
- Per group: header line `{wgn_name} {lat} {lon} {elev} {n_years}`, column
  header line, then 12 monthly rows (Jan → Dec).
- Column mapping (verified against the reference `weather-wgn.cli`):
  `TMPMX→tmp_max_ave`, `TMPMN→tmp_min_ave`, `TMPSTDMX→tmp_max_sd`,
  `TMPSTDMN→tmp_min_sd`, `PCPMM→pcp_ave`, `PCPSTD→pcp_sd`,
  `PCPSKW→pcp_skew`, `PR_W1→wet_dry`, `PR_W2→wet_wet`, `PCPD→pcp_days`,
  `RAINHHMX→pcp_hhr`, `SOLARAV→slr_ave`, `DEWPT→dew_ave`, `WNDAV→wnd_ave`.

**`weather-sta.cli`** — one row per station, columns
`name/wgn/pcp/tmp/slr/hmd/wnd/pet/atmo_dep`:

- `name` = station name, `wgn` = its WGN group name (= station name, per
  above).
- `pcp`/`tmp`/`slr`/`hmd`/`wnd` = the written data file's stem (no
  extension) if that variable was written for the station, else `"sim"`.
- `pet`, `atmo_dep` = `"null"` (not computed by swatprep — out of scope).

> **Assumption flagged for follow-up verification:** the "file stem, no
> extension" convention for the `pcp`/`tmp`/... columns is based on general
> SWAT+ I/O knowledge, not a directly observed example — both reference
> `weather-sta.cli` files available during design had every row set to
> `"sim"` (no station in either reference actually links to an observed
> file). Verify against a real SWAT+ Editor-generated `weather-sta.cli`
> that references observed files before relying on this in production.

## Testing

Existing tests directly affected:

- `tests/test_pcp_converter.py`, `tests/test_tmp_converter.py` — test
  classes being deleted; rewritten against `StationWeatherConverter`.
- `tests/test_weather.py` — has assertions locked to the old SWAT2012
  header/date format; updated for the fixed format.
- `tests/test_weather_plus.py` — data-file format unchanged; extended to
  cover the new `weather-sta.cli` / `weather-wgn.cli` output.

New tests to add:

- `StationWeatherConverter` reads real-shaped SWAT2012 raw input (pcp
  single-column, tmp `tmin,tmax`) into a correct `WeatherResult` (dates,
  values, station id/name/lat/lon/elev mapped correctly from uppercase
  master columns).
- `WeatherWriter` (fixed) produces the corrected format: no header block,
  un-offset start date, `master_pcp.txt`/`master_tmp.txt` with uppercase
  columns and prefixed `NAME`.
- Round-trip: reference-shaped input → `StationWeatherConverter` →
  `WeatherWriter` (target=swat2012) output is re-readable by
  `StationWeatherConverter` and yields the same data.
- `SWATPlusWeatherWriter` emits valid `weather-sta.cli` / `weather-wgn.cli`
  (correct column layout, correct 12-row-per-station WGN blocks, correct
  `"sim"` fallback when a variable file wasn't written).
- CLI test for `swatprep convert weather` with `--target swat2012`,
  `--target swatplus`, and both together (multi-target subdirectory
  layout).

## Out of scope

- `converters/climate.py` (`DayFilesConverter`) and
  `converters/streamflow.py` — unrelated input shapes, not touched.
- WGN grid-cell grouping (multiple stations sharing one WGN entry by
  spatial grid, as SWAT+ Editor does for `"sim"` stations) — swatprep's
  one-WGN-per-station mapping is simpler and sufficient for its current
  "SWAT+ output from observed station data" use case.
- `pet` and `atmo_dep` columns in `weather-sta.cli` — swatprep does not
  compute these; left as `"null"`.
